# Оптимизатор приоритетов (идея Nemo, 24.10.2026)

В разделе результатов добавлены ползунок бюджета, предпочтения и обязательные условия, три слота: лучший, дешевле и дороже. Backend: POST /api/v1/optimize. Для четырёх демо-отелей применяется точный детерминированный перебор с жёсткими ограничениями и весами предпочтений. OR-Tools/Z3 **не установлен**: при 4 вариантах полный перебор даёт точный результат без дополнительной зависимости. Это не заявка на реализацию OR-Tools.

Данные об офисах, музеях, пеших маршрутах и видах на море пока не подтверждены, поэтому такие обязательные условия честно дают «нет вариантов», а не выдуманные соответствия. Разница модельных цен не является ценой конкретного пожелания. Матрица маршрутов не рассчитана. Для неё нужны координаты мест назначения и проверенный роутинг, а также политика кэширования.

MCP endpoint `/mcp` есть, инструменты доступны по JSON-RPC, но end-to-end вызовы к внешним API, авторизация MCP и совместимость со сторонним MCP-клиентом не подтверждены. Для openrouteservice нужен ключ. Docker отсутствует в среде сборки, поэтому запуск `docker compose up --build` не проверен.

## Экран

Адаптивная вёрстка: ширина контейнера до 1100px; 3 колонки на широких экранах и автоматический перенос на узких. Для проверки использовать 390×844 (телефон), 768×1024 (планшет), 1366×768 и 1920×1080 (desktop). Это тестовые viewport, не требуемое разрешение устройства.

## Запуск

`docker compose up --build` и открыть http://localhost:8080 . Тесты: `python -m pytest -q`. Для frontend: `cd frontend && npm ci && npm run build`. Проверить API `POST /api/v1/optimize` с полями `spec`, `priorities`, `must_have`.
