# Решения по материалам 26.10.2026

Использованы: `Дизайн AI-агента путешествий.zip` (handoff v2), `Odin Zapros v3.html`, `ТЗ_Один_запрос.md`, ранее сохранённые решения Q&A от 25.10. Полный текст конкурсного задания в репозиторий не копируется.

Архив прямо называет HTML дизайн-референсом, а его данные — моками. В нём только отели; v3 и новое ТЗ расширяют сценарий на всю поездку. Последнее указание команды сохраняет один регион и самостоятельно собранные открытые источники. Поэтому не перенесены фиктивные отзывы, отели, брони, заранее заданные суммы и имитация поиска таймерами.

| Часть | Реализация / ограничение |
|---|---|
| Стиль v3 | Onest из встроенного шрифта HTML; синий #1F5BFF, лайм #C8F560, радиусы, чипы, мобильный старт. Существующие рабочие экраны сохранены и приведены к этим токенам; это не полная пиксельная копия всех состояний |
| Один запрос | Новый `/understand`: явные условия, отдельные допущения, вопросы только по отсутствующим датам/направлению/составу; неизвестный возраст ребёнка запрашивается отдельно |
| Бюджет | Не спрашивается обязательно; «не задан» отделено от нуля. Изменение бюджета в чате включает ограничение снова |
| Три направления | Не показываются: демо-регион — Большой Сочи и Сириус. Чужой город не заменяется автоматически. Запрос о тёплом море получает предупреждение |
| Отели | До трёх основных предложений из четырёх проверенных карточек; дополнительные варианты сохранены. Неподтверждённые обязательные услуги исключают предложение |
| Открытая география | Снимок OSM + Copernicus/Open-Meteo; дата, лицензия, исходные теги и ссылки. Связь с карточками только по проверенным ID |
| Транспорт и полный план | Резервы в бюджете и ручные события. Настоящих расписаний/билетов и проверки стыковок нет, зелёная надпись «всё сходится» для них не рисуется |
| Пересборка | Предложение изменений, предварительный пересчёт, применение по версии, сохранение подходящего отеля |
| Оформление | Тестовый заказ и отмена; никаких карт, паспортов, обещаний реальной брони |
| LLM | Опциональное OpenAI-совместимое API; на этапе понимания есть fallback. Эвал качества живой модели ещё нужен |
| Метрики | Проверки поведения и реальное число просмотренных карточек. Официальные веса, пороги и обязательное число отелей не придумываются |

Для дальнейшего полного соответствия широкому ТЗ нужны отдельные работы: модель расписаний с IANA-поясами, независимая проверка стыковок, операции закрепления компонентов, верификатор LLM-текстов, расширенный eval и финальный скринкаст. Их отсутствие не скрыто демонстрационными заглушками.
