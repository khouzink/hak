# Реальные MCP/API и стоимость масштабирования

Проверено 26.10.2026. MCP — протокол доступа к инструментам, а не отдельная бесплатная база отелей. В приложении работает собственный read-only сервер `/mcp`; инструменты используют открытые API.

| Инструмент / данные | Источник | Цена и границы |
|---|---|---|
| `geocode_city` | Open-Meteo Geocoding / GeoNames | Без ключа; кэш 7 дней. Условия коммерческого доступа проверяются отдельно |
| `discover_hotels` | Overpass / OpenStreetMap | Без ключа; кэш 24 часа. Возможны таймауты; цен и наличия нет |
| `walking_route` | FOSSGIS OSRM foot / OSM | Без ключа; интервал >=1,1 с, кэш 7 дней. Публичный сервер не для массовых запросов |
| `nearby_verified_pois` | Подготовленный снимок OSM + OSRM | При чтении нет внешних запросов; дата и источник в JSON |
| Высоты отелей | Open-Meteo Elevation / Copernicus DEM | Снимок включён; высота точки не доказывает отсутствие лестниц или уклон маршрута |
| Маршруты ORS | openrouteservice | Сменный провайдер; пользовательский ключ проверен живым запросом в v8, действуют квоты сервиса |

Реально проверены официальным Python MCP SDK 1.26.0: initialize, list_tools, geocode_city, walking_route, nearby_verified_pois; повтор маршрута возвращает cache_hit=true. Протокол 2025-03-26, JSON-ответы Streamable HTTP. SSE отсутствует (GET возвращает 405); уведомления — 202 без тела. Совместимость со всеми клиентами не заявляется.

```sh
# В отдельном окружении интеграционного клиента, чтобы не менять runtime-зависимости:
pip install mcp==1.26.0
python scripts/verify_mcp_live.py http://127.0.0.1:8080/mcp
```

Для внешнего доступа задайте MCP_API_KEY и MCP_REQUIRE_AUTH=1, используйте HTTPS на reverse proxy. Клиент передаёт Authorization: Bearer KEY. Есть проверка Origin, лимит тела 32 KiB и ограничение частоты. По умолчанию Docker слушает только 127.0.0.1. Эти меры не заменяют общую авторизацию пользователей продукта.

Обновить небольшой готовый набор без ключей:

```sh
python scripts/build_demo_walks.py
```

Скрипт запрашивает небольшой фрагмент центра Сочи и максимум 6 маршрутов; сохраняет старый снимок при ошибке. Для крупных обновлений — собственные сервисы и региональные выгрузки. Старый scripts/build_poi_matrix.py остаётся опциональным ORS-провайдером.

## Почему это недорого и как расширять

Стартовое демо не требует платных ключей или LLM. Каталог, подбор, бюджет, порядок заказа и снимки работают локально. Внешние запросы выполняются явно; кэш уменьшает повторные обращения. Содержимое снимка используется подбором приоритетов, а live MCP доступен внешнему агенту. Автономного LLM-оркестратора, выбирающего инструменты, пока нет.

Новому региону нужны собственный набор подтверждённых отелей, источники и снимок POI. Подготовленный каталог v8 покрывает восемь направлений. Геокодирование произвольного города за пределами снимков не равно поддержке его бронирования.

Для горизонтального масштабирования ещё нужны PostgreSQL вместо локального SQLite, общий Redis-кэш/лимитер, фоновые обновления снимков и аккаунты. Текущие лимитеры действуют внутри одного процесса; запуск множества реплик на публичный OSRM обойдёт общий лимит провайдера и недопустим. Меняются OSRM_FOOT_URL, OVERPASS_URL, GEOCODING_URL; самохостинг открытого ПО требует оплаты инфраструктуры. Подключаемая LLM оплачивается отдельно; локальная модель тоже потребляет ресурсы. Нулевая стоимость и неограниченная производительность не обещаются.

Open-Meteo: бесплатный сервис для некоммерческого использования, условия коммерческого сервиса отдельные. FOSSGIS: максимум 1 запрос/с, без массового использования. Не подключаем множество дублирующих MCP ради количества: это не добавляет данных и усложняет эксплуатацию.

Источники условий: https://routing.openstreetmap.de/about.html ; https://open-meteo.com/en/pricing ; https://www.openstreetmap.org/copyright ; https://modelcontextprotocol.io/specification/2025-03-26/basic/transports .

Нет реального инвентаря Островка, актуальных тарифов, покупки авиабилетов или настоящего бронирования. Названия и география реальны; цены, доступность и заказы демонстрационные.

## Обновление v8

Теперь пять MCP-инструментов: geocode_city, discover_hotels, walking_route, nearby_verified_pois, weather_forecast. Последний возвращает прогноз только в доступном временном окне; исторические средние не выдаются за прогноз. Живые `/context` и `/walking` доступны пользователю в интерфейсе и используют те же адаптеры.

Пользовательский ORS-ключ найден в переданных материалах и реально проверен: HTTP 200, пешеходные расстояние и время. Ключ хранится только в локальном `.env`, исключён из Docker image и архива. В переносимой сборке по умолчанию используется OSRM без ключа. Оба варианта сохраняются как сменные провайдеры.

Подготовленные снимки расширены до 8 направлений, всего 795 объектов. Это ограниченные участки городов с разной полнотой тегов; не глобальная база наличия и тарифов. Восемь исторических сводок Open-Meteo за 2016–2025 включены отдельно.
